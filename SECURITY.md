# Security and privacy

Do not open public issues containing credentials, personal information, private server addresses, or sensitive logs. If you find a potential exposure, contact the maintainer through a private GitHub channel where available.

Before committing, review staged files for API keys, tokens, .env files, private datasets, personal memory stores, and configuration exports. Git ignore rules do not remove secrets already committed to history. Revoke exposed credentials and remediate history where appropriate.

No production deployment or security audit is claimed.
